## 2. 审查中修正的判断

| 事项 | 最终处理 |
|---|---|
| R01 不可变性 | 确认，当前 14 处映射字段有可变性问题。修复针对公开契约使用，不承诺抵御同进程恶意 Python |
| R02 实验身份 | 确认契约覆盖不足；实现遵循原元组哈希定义，因此需 ADR，不是静默修一个函数 |
| R06 退役审批 | Opus 撤回“图与正文自相矛盾”：revalidation failed 是触发条件，不是免审批；ADR-0006 §3.6 的审批规则仍适用 |
| LLM 输入输出 | Opus 撤回“仅哈希足够”：06-experiment 要求完整输入输出；存储或可取回引用仍是后续缺口 |
| dict 依赖表达 | 字符串映射可以表达 name@version→hash；问题是命名、覆盖及解析校验，不必为形式增加抽象 |
| Hash 排除字段 | 不全局排除 ID/审计时间；Profile status 单独处理，provenance 保留 |
| 种子与 Run | 推荐 concrete seeds 留在实验哈希中；每次运行独立 run_id，不引入 seed DSL 或 run_id 算法冻结 |
| 版本与旧数据 | 推荐共同构成未发布 2.0.0；外部历史数据存在性证据不足，不能宣称无迁移影响 |
| R04 完整验证门 | 门覆盖与 reported-only/INCONCLUSIVE 语义需明确，不能把整个未来 Runner 实现追加为本轮任务 |
| R11 计数 | 权威账本以后实现；当前不得把自报计数描述为已强制防护 |
| R13 Provider | 保留为文档范围决定；不自行选择一份同级文档，更不自动实现十套接口 |
| R14 文档状态 | Codex 已修正当前状态与部分过期 README；冻结架构文档的后续同步随获批 ADR 进行 |

## 4. 两个独立决策包

### D-11：不可变载荷

- **问题：**是否批准 ADR-0008 的方案 A？
- **推荐：**只读 Mapping、别名隔离、默认值同路径、Profile 特定哈希边界、有限数值与 v1 只读兼容。
- **影响：**属于下一次未发布的 2.0.0；不是修改统计阈值，不新增基础设施。
- **选项：**A 批准该方案；B 指定修改后再审；C 暂缓。
- **未决定时：**不编码、不发布，Phase 0 保持开启。

### D-12：实验身份

- **问题：**是否批准 ADR-0009 的小方案 A？
- **推荐：**将策略/风控/Outcome 和直接依赖内容绑定纳入复现元组；实际种子留在哈希中；run_id 区分每次运行；报告绑定运行；规则选择包含唯一引用和哈希。
- **影响：**修订已有实验身份语义，并与 ADR-0008 一起完成 v2；不实现 Runner/Registry，不冻结未来 run_id 算法。
- **选项：**A 批准该方案；B 指定修改后再审；C 暂缓。
- **未决定时：**不以当前不完整实验哈希宣称晋升证据完整。

若同时批准两个方案，可明确回复：“批准 ADR-0008 和 ADR-0009 的方案 A，授权 Opus 串行执行 B1、B2；不合并 main。”这只授权该范围，不授权 B3、宪法批准或其他 Phase。

## 5. 后续最小闭环的价值门槛（未批准）

固定数据输入 → 完整规格 → 确定性运行 → 可追溯报告 → 成功/失败全部保存。先证明能复现，能识别未来数据、切分和成本错误，再以预登记的噪声/植入效应对照评估判别能力。方法与判据在看结果前确定；本轮不选择最终统计阈值。

若维护成本上升却没有改善复现、错误识别或研究效率，应缩减设计。LLM 发现、Router、演化、实盘和分布式运行均不在当前推进范围。Q-7、H-3～H-7 继续未决。
