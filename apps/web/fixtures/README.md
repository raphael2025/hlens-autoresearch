# apps/web/fixtures

Example report files for every console report kind, laid out exactly like a real report root
(`<kind>/<id>.json`) so this directory can be passed straight to
`apps.api.create_app(reports_root=...)` for local `npm run dev` use — see
[../README.md](../README.md) "用 `apps/web/fixtures/` 快速起一个有数据的后端".

Every file is generated by `research/reports`' real writers over small, existing test fixture
objects — the JSON here is byte-identical to what those writers produce for those objects, not
hand-written example data. All of them (2026-09-26, all ten kinds) are generated by one committed
module and pinned by its tests:

    uv run python -m tests.research.reports.test_console_fixture_writers

regenerates them, and that module's pytest fails unless each `<kind>/` directory holds exactly
the files the real writers produce for those objects, byte for byte, and nothing else. Writers are
append-only and every id is a content hash, so after changing a writer's payload shape or a reused
fixture builder, delete the stale file under the affected `<kind>/` first.

## Current fixtures (contract 2.1.0)

One per kind, built at the current contract version:

- `validation_report/`: `write_validation_report` over the `_validation_report()` builder of
  `tests/research/reports/test_writers.py` plus one exact gate (`value_exact` / `threshold_exact`,
  ADR-0052 §1; TEST ONLY values whose exact text has more digits than the float), so the console's
  exact display is exercised.
- `research_loop_round/`: `write_research_loop_round` over `_loop_record()` of the same module. A
  `research_loop_round/` fixture must be a valid `LoopRoundRecord` (ADR-0050) named by its
  `record_hash`, or the store refuses it; `_loop_record()` builds a six-stage completed round via
  `tests/apps/loop_records.py`.
- `state_strategy_matrix/`, `router_paper_run/`: `write_state_strategy_matrix` /
  `write_router_paper_run` over `_matrix_with_backtest()` of `test_writers.py` (the fixtures of
  `tests/research/experiments/test_state_strategy.py`) and the run of
  `tests/research/router/test_paper.py`.
- `gate_calibration/`: `write_gate_calibration_report` over
  `run_gate_calibration(_toy_setup())` from `tests/research/synthetic_lab/test_gate_calibration.py`
  — the toy, Profile-reading detector (TEST ONLY), not the full G0→G4 pipeline, so the fixture
  stays small while still exercising both a noise arm (false-positive rate) and a planted-effect
  arm (power) under two candidate Profiles (`TOY_LAX` / `TOY_STRICT`).
- `router_stop/`, `state_diagnostics/`, `event_statistics/`: `write_router_stop` /
  `write_state_diagnostics` / `write_event_statistics` over, respectively, the all-routes-flat stop
  of `tests/research/router/test_router_completion.py` (`_or_stop(FLAT, LIFECYCLE)`), the
  hand-checked two-state series of `tests/research/states/test_state_diagnostics.py`
  (`diagnose(SERIES, SPACE, min_run=2)`) and the four statistics of
  `tests/research/events/test_event_stats.py` bound to two run hashes.
- `paper_deviation/`: `write_paper_deviation` over `deviation()` of
  `tests/research/router/test_paper_deviation.py` — the `test_paper.py` router run vs strategy A run
  alone through the same backtester (the declared reference).
- `degradation_check/`: `write_degradation_check` over the check of
  `tests/research/reports/test_degradation_writer.py` (`write_fixture`) — TEST ONLY thresholds and
  metrics (one breached, one within, one missing), not Profile values. A second, **variant**
  file `50f536888a5b49fec15e11737bd107101d909617449b16881de60d5139f37d9d.json` is the same monitor
  with no recent value at all (`write_insufficient_evidence_fixture`: every metric missing,
  `"insufficient_evidence": true`); it is produced by the generator's `VARIANT_WRITERS` and pinned
  by id in `tests/apps/report_fixtures.py` (`VARIANTS`).

## Legacy readable fixtures (contract 2.0.0)

Kept next to the current file so the API and the console keep proving they still read a report
written before contract 2.1.0. The file names cannot change (each is the report's content hash,
which the store checks), so they are marked here and pinned by id in
`tests/apps/report_fixtures.py` (`LEGACY_2_0_0`):

| kind | legacy 2.0.0 file |
|---|---|
| `validation_report/` | `a29b0ab7fb27edbc09cda37b01ad323c0c005f32694547ae45afd0e94333072b.json` (float-only gate) |
| `state_strategy_matrix/` | `5940a5de3bde080ff156d564ce582d73d1db85623fea163b53ba925030fec21c.json` |
| `gate_calibration/` | `deaba5047218eeff080ed1e1ae588ba8e13a4f6ea3b6557fcab6ea3ffbe5fc07.json` |

They were first produced by a throwaway script before contract 2.1.0; they are now reproduced by
the same committed module (`regenerate_legacy`): the same builders (the validation report without
the exact gate) in a fresh interpreter that imports them inside
`contract_schema_version_scope("2.0.0")`, and its pytest requires the result to be byte-identical
to these files. `research_loop_round/` and `router_paper_run/` have no legacy file: their committed
files already are the current (2.1.0) writers' output, so there is no older file to keep.

`tests/apps/test_console_fixtures.py` loads every fixture here through `apps.api`'s `ReportStore`
(and the `/reports/...` HTTP endpoints) and fails if any `ReportKind` has no fixture file, so this
directory cannot silently drift out of sync with `ReportKind`. The console's node / component tests
(`src/lib/*.test.ts`, `src/pages/reportPages.test.tsx`) parse and render every fixture of a kind,
legacy ones included.
