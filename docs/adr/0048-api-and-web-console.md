## 裁决

1. `apps/api`：FastAPI 应用工厂 `create_app`（Provider 注入），只做编排与校验，不含业务规则、不 import `research/`；OpenAPI 导出到
   `apps/api/openapi.json` 并由测试校验为最新。首批只读端点：健康、契约清单、生命周期转移、知识检索。
2. `apps/web`：Vite + React + TypeScript 骨架，只经 OpenAPI 生成的类型访问后端（`npm run gen:api`）；依赖只声明、未安装（项目本地
   安装与构建属调试阶段；不涉及系统软件）。
3. 写操作（实验登记、生命周期推进）等 P7 / P8 / P11 框架后再暴露，并须经授权服务（ADR-0011 的主体与授权约束）。

## Implementation note (console, 2026-09-25)

Builds out the read-only research console on top of the ADR-0048 skeleton, still
FRAMEWORK_IMPLEMENTED / NOT_VALIDATED and still within the original 裁决 above (no new decision;
this only records what was implemented).

**apps/api**

- `apps/api/store.py`: `ReportStore`, a read-only abstraction over JSON artifact files written by
  the research plane at `<reports_root>/<kind>/<id>.json` — `apps/api` still never imports
  `research/` (tested by `tests/test_architecture_boundaries.py`). `ReportKind` covers the four
  kinds the task asked for: `validation_report`, `research_loop_round`, `state_strategy_matrix`,
  `router_paper_run`. Every report is served through one minimal envelope
  (`ReportEnvelope`: `kind`, `id`, `created`, `payload: dict`, `content_hash`), so a new report
  kind is just a new subdirectory — no contract or endpoint change. `content_hash` is the SHA-256
  of the payload's canonical (sorted-key, compact) JSON.
- New endpoints on `create_app` (now takes `reports_root: Path | None = None`, default `None` ->
  every `/reports/*` call returns an empty list / 404, never an error):
  `GET /reports/{kind}` (list) and `GET /reports/{kind}/{id}` (detail). `{kind}` is validated by
  FastAPI's enum path param (unknown kind -> 422); `{id}` is validated against a safe-filename
  pattern and resolved-path containment check before touching the filesystem (path traversal ->
  400; a malformed JSON file is skipped in listings and raises on direct fetch).
- `apps/api/openapi.json` regenerated (`python -m apps.api.openapi`) to include the new routes and
  the `ReportEnvelope` / `ReportKind` schemas; the existing "committed OpenAPI is current" test
  still passes.
- New tests: `tests/apps/test_reports.py` (store unit tests with `tmp_path`, plus the HTTP layer
  via `TestClient`), covering empty-store defaults, per-kind scoping, malformed-file handling and
  path-traversal refusal.

**apps/web**

- Five read-only pages wired to the endpoints above, each carrying a
  "SIMULATED / NOT_VALIDATED" banner and none of them any order / trading UI (H10): Dashboard
  (health + contract count + per-kind report counts), Validation Reports (list + detail with a
  gate-results table), Research Loop (round timeline, an ECharts bar chart of budget used per
  round, failure counts), Lifecycle (the transition table already served by `/lifecycle/transitions`),
  Knowledge Search (unchanged behaviour, moved into its own page).
- `src/api.ts`: a thin fetch client typed off `src/api.d.ts` (generated by
  `npm run gen:api` from the committed `apps/api/openapi.json`, and itself committed).
  `/knowledge/search` is declared `response_model=None` in `apps/api/app.py`, so it has no
  generated response schema; its shape is typed by hand from `core.domain.research.KnowledgeItem`
  with a comment explaining why.
- Dependencies were installed locally (`apps/web/node_modules/`, gitignored — a project-local
  `npm install`, not a system install; `apps/web/package-lock.json` is committed) and both
  `npm run gen:api` and `npm run build` (`tsc --noEmit && vite build`) were run and pass, all
  wrapped in `systemd-run --user --scope --quiet -p MemoryMax=2G -p MemorySwapMax=0`.

**Left open (unchanged from the original 裁决)**: no write endpoints; state-strategy-matrix and
router-paper-run reports are served by the API and counted on the Dashboard but have no dedicated
page yet (not asked for by this task); a real research-plane writer for these report directories
does not exist yet (P6 / P9 / P10 framework land the report shapes this store already reads
generically).

## Implementation note (report writer, 2026-09-25)

Adds the research-plane counterpart the previous note left open: a writer under `research/reports/`
for each of the four report kinds `apps.api.store.ReportStore` already reads. Still
FRAMEWORK_IMPLEMENTED / NOT_VALIDATED, still within the original 裁决 (no new decision; write
endpoints on `apps/api` itself remain out of scope per 裁决 §3).

**Design: where the shared envelope / canonical-JSON rule lives**

`ReportStore` recomputes its own `content_hash` from the parsed payload on every read, independent
of on-disk formatting — so the writer never has to reproduce the store's envelope or match its hash
function byte-for-byte. What the writer does need is its own deterministic, canonical serialization
(sorted keys) so that "same content" comparisons for the append-only rule are format-stable. Two
options were on the table: reuse `apps/api/store.py`'s private `_canonical_json` / `_content_hash`,
or reuse `core.domain.base.canonical_json` (the project's one existing canonical-JSON definition,
docs/architecture/02-domain.md §3, already used by every `Contract.content_hash()`). Decision:
**core**. `apps/api/store.py`'s encoder is private (underscore-prefixed, not in `__all__`) and
differs only cosmetically (`ensure_ascii=True` vs. core's `False`) — reusing it would reach into
another Plane's internals for a rule that already has an authoritative, public definition upstream
of both `apps/` and `research/`. No new contract model was added; `research/reports/envelope.py`'s
`write_report_file` is a small pure function (`root, kind, id, payload -> WrittenReport`) built on
that one existing helper.

**research/reports/**

- `envelope.py`: `write_report_file(root, kind, id, payload)` — writes `<root>/<kind>/<id>.json`
  atomically (temp file + `os.replace`); writing identical content already on disk is a no-op
  (`WrittenReport.written = False`); writing different content under an existing id raises
  `ReportConflict` (append-only, H6-adjacent: a report is never silently rewritten). `id` is
  validated against the same safe-filename pattern `apps/api/store.py` uses.
- One writer per kind, each deriving `id` from **the object's own content / result hash** — every
  one of the four already carries one, so no new hashing scheme was introduced:
  `validation.py` (`ValidationReport.content_hash()` — not `report_id`, which the model's own
  docstring calls an external label, not a content identity), `loop.py`
  (`LoopRecord.record_hash`, importing `apps.worker.loop` — the one sanctioned research→apps
  exception, ADR-0049, already used by `research/loop/compose.py`), `matrix.py`
  (`StateStrategyMatrix.matrix_hash`; the payload mirrors that hash's fields rather than importing
  a private helper from `research/experiments/state_strategy.py`, which this batch does not touch),
  `router.py` (`RouterPaperRun.run_hash`). Because the id is content-derived, two different report
  contents can never collide on id by construction; `ReportConflict` is exercised directly at the
  `write_report_file` level and by forcing the same id under a kind's directory in tests.
- `research/loop/compose.py` gained `run_unattended_and_report(loop, rounds, *, reports_root=None)`:
  a thin wrapper around `ResearchLoop.run_unattended` that also writes every `LoopRecord` produced
  when `reports_root` is given (`None`, the default, writes nothing — identical to calling
  `run_unattended` directly). This is the P11 loop's optional report-root hook the task asked for.

**Tests**: `tests/research/reports/test_writers.py` (the generic writer's determinism / idempotence
/ conflict-refusal / unsafe-id rejection, and each of the four kind-specific writers round-tripped
through both `ReportStore` and `apps.api.create_app`'s `/reports/...` endpoints via `TestClient`);
`tests/research/loop/test_reports_hook.py` (the P11 e2e fixture run through
`run_unattended_and_report`, with and without a `reports_root`, including that replaying the same
rounds again leaves the on-disk files byte-identical).

**Docs**: `research/reports/README.md` (new), a `research/README.md` row, and
`apps/web/README.md` extended with a concrete snippet for pointing `create_app(reports_root=...)`
at a directory `research/reports` writers fill.

**Left open**: the four payload shapes are display-oriented summaries picked by this batch, not
exhaustive field-for-field dumps of every object (e.g. `router_paper_run` omits the full combined
target-position series); extending them is routine follow-up, not a contract change. No write
endpoints or report-root pruning/retention policy — unchanged from the original 裁决.

## Implementation note (console pages, 2026-09-25)

Adds the two console pages the first console note left open (`state_strategy_matrix` and
`router_paper_run` were already served by `apps/api` and counted on the Dashboard, but had no
dedicated page). Still FRAMEWORK_IMPLEMENTED / NOT_VALIDATED, still within the original 裁决 (no
new decision).

**apps/web**

- `State × Strategy Matrices` (`src/pages/StateStrategyMatrices.tsx`): list + detail. The detail
  view is an ECharts heatmap of `count` / `mean` / `hit_rate` / `total` (rows) x state (columns),
  each row independently min-max normalized for color (the metrics are on unrelated scales; the
  tooltip always shows the raw value, never the normalized one) — plus a table with every cell's
  sample count, and a note when a matrix carries no P5/P2 source hashes (a plain return x state
  mapping, per `research/experiments/state_strategy.py`).
- `Router Paper Runs` (`src/pages/RouterPaperRuns.tsx`): list + detail with (a) a weights / switch
  timeline (stacked-area routed weights per strategy, turnover as bars on a second axis marking
  switches) and (b) gross- vs. net-of-switching-cost equity, both ECharts line/bar charts. Neither
  page has any order / trading UI (H10); both carry `SimulatedBanner`, and the router page adds an
  explicit "PAPER ONLY" line.
- `research/reports/router.py`'s payload gained `gross_equity_curve` / `net_equity_curve` (each
  point's `time` / `cash` / `equity` / `gross_exposure`) — the equity-vs-cost chart needs the point
  series, not just the endpoints already on the payload. Display-only: `run_hash` already binds
  `gross_result_hash` / `result_hash`, so the new fields carry no additional identity (see
  `research/reports/router.py`'s docstring and `research/reports/README.md`). This is the kind of
  routine payload extension the previous note flagged as open, not a contract change.
- Code splitting (`src/App.tsx`, `src/lib/echarts.ts`, `vite.config.ts`): all seven pages are
  `React.lazy`-loaded, and the ECharts-using pages now share one tree-shaken setup module
  (`echarts/core` + only the chart types / components used: bar, line, heatmap, grid, legend,
  tooltip, visualMap, canvas renderer) instead of importing the full `echarts` package.
  `build.rollupOptions.output.manualChunks` also splits `zrender` (ECharts' renderer layer) into
  its own chunk. Before this batch `npm run build` emitted one ~1.19 MB chunk; it now emits several
  chunks, the largest ~375 kB, with no "chunk larger than 500 kB" warning.
- `apps/web/fixtures/`: example `state_strategy_matrix/` and `router_paper_run/` report files,
  generated by the real `research/reports` writers over the project's own test fixtures (so they
  are byte-identical to what those writers produce, not hand-written), laid out as a real report
  root so `apps.api.create_app(reports_root=Path("apps/web/fixtures"))` serves them directly for
  local `npm run dev` use (`apps/web/README.md` documents this).
- `apps/api/openapi.json` / `src/api.d.ts` unchanged (no `apps/api` endpoint changed); `npm run
  gen:api` was re-run to confirm this (no diff).

**Tests**: `tests/research/reports/test_writers.py`'s router round-trip test extended to assert the
new equity-curve fields; `tests/apps`, `tests/test_architecture_boundaries.py`,
`tests/test_docs_consistency.py`, `tests/research/reports`, `tests/research/router` all still pass,
along with `ruff check`, `ruff format --check` and `mypy` over the whole project, and `npm run
gen:api` / `npm run build` (all under the `MemoryMax=2G` cap).

**Left open**: no write endpoints (unchanged from the original 裁决); `validation_report` /
`research_loop_round` still have no fixture files under `apps/web/fixtures/` (only the two kinds
this batch's pages need).
