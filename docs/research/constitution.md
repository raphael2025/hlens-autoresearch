|---|---|

> 本文件是系统的"宪法"。它的存在是为了防止研究系统自我欺骗。
> **任何人（包括 AI Agent）不得为了让某个实验通过而修改本文件。**

---

## 第一章 基本原则

- **A1 证伪优先**：每个假设在运行前声明预期方向与最小有意义效应量。
- **A2 预登记**：假设、数据切分、指标、成本模型在运行前登记且不可变。
- **A3 全记录**：每一次尝试都计入 trial count；失败与成功同等保存。
- **A4 裁判确定性**：通过/失败由确定性程序判定，不由 LLM 或主观判断决定。
- **A5 规则稳定**：规则修改只前向生效；不得追溯改变已判定对象的结果。
- **A6 成本真实**：所有收益指标必须扣除交易成本、滑点与资金费率。

## 第二章 泄漏防护（C-L）

| ID | 规则 |
|---|---|
| C-L1 | Point-in-time：只使用 `available_time ≤ t` 的数据 |
| C-L2 | Outcome 永不作为输入 |
| C-L3 | 标准化 / 分位 / 模型拟合只能用训练窗口内数据 |
| C-L4 | 幸存者偏差：标的池按当时可交易集合构建（含已下架标的） |
| C-L5 | 时间序列交叉验证需 purging 与 embargo（间隔 ≥ 最长 Outcome horizon） |
| C-L6 | 自动泄漏检测：随机打乱标签/时间平移测试必须使效应消失 |

## 第三章 数据切分（C-S）

| ID | 规则 |
|---|---|
| C-S1 | 时间顺序切分：Train → Validation → **Sealed OOS** |
| C-S2 | Sealed OOS 对每个假设族只开封一次；开封事件审计记录 |
| C-S3 | OOS 区间长度与起点在 Constitution 版本中固定（数值待定：**TBD-1**） |
| C-S4 | 滚动前推（walk-forward）评估作为样本内稳健性的一部分 |

## 第四章 统计显著性（C-T）

| ID | 规则 |
|---|---|
| C-T1 | 报告多重检验校正后的显著性（如 Deflated Sharpe Ratio 或等价方法），trial count 取假设族累计值 |
| C-T2 | 最小样本量：交易次数 / 独立事件数下限（**TBD-2**） |
| C-T3 | 置信区间优先于点估计；使用 block bootstrap 等考虑自相关的方法 |
| C-T4 | 基准比较：必须优于简单基准（买入持有、随机进出、反向策略）（**TBD-3**） |

## 第五章 稳健性（C-R）

| ID | 规则 |
|---|---|
| C-R1 | 参数稳定性：邻域参数表现不得断崖式下降（**TBD-4**） |
| C-R2 | 状态分解：按 Market State 分解表现，不得依赖单一状态中的少数事件 |
| C-R3 | 跨标的 / 跨时期：在声明的适用范围内检验 |
| C-R4 | 成本压力：成本 ×2 下仍需满足最低标准（**TBD-5**） |
| C-R5 | 容量：估计冲击成本与可承载规模 |

## 第六章 复现（C-P）

| ID | 规则 |
|---|---|
| C-P1 | 复现元组完整（06-experiment.md §2） |
| C-P2 | 重跑结果一致（确定性部分按位 / 声明容差） |
| C-P3 | 不可复现 = FAILED |

## 第七章 晋升与退役（C-G）

| ID | 规则 |
|---|---|
| C-G1 | PRODUCTION_CANDIDATE → ACTIVE 需人工批准 |
| C-G2 | ACTIVE 对象需定义劣化监控阈值（登记时声明） |
| C-G3 | 退役原因写入 Failure Registry |

## 第八章 修改程序

1. 提交 ADR（状态 Proposed），说明修改动机——**动机不得是"某个实验因此能通过"**。
2. 用户批准后发布新版本号。
3. 新版本只适用于此后登记的实验。
4. 修改历史保留在本文件末尾。
