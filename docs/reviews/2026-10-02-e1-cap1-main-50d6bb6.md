# E1-CAP-1 正式探针：`main@50d6bb6`（2026-10-02，完整协议）

## 结论

- **数值判定：PASS**（`status=complete`、`capacity_verdict=PASS`、`e1_cap1_evidence=true`；协议符合项全部为真：M=256、N=10k/100k/500k、每 N 3 次、代码行与 `main` 一致、探针与 HEAD 一致、未开诊断）。
- **E1-CAP-1 仍未关闭。** [E1 review](2026-09-27-e1-review.md) 的关闭标准要求"同一 M 时，大 N 的新增峰值不得按 N 或 batch 数线性增长，并与结构上界相互印证"。本次数据显示 Iceberg 表元数据项随 snapshot（= 批次）数线性增长：`metadata` stage 1.7 → 3.7 → 17.7 MiB，`resume` 增长 31.2 MiB，距 32 MiB 门槛仅 0.8 MiB。根因与处置见 [ADR-0108](../adr/0108-canonical-commit-granularity-and-metadata-growth.md)（Proposed）。探针每个单元从空表开始，生产中 snapshot 跨单元累积、永不过期，该项会继续增长。

## 判定规则

每个 stage：`growth = max(delta) − min(delta)`，跨全部 N 与 repeat，须 ≤ 32 MiB（`GROWTH_LIMIT_MIB`）。delta = stage 窗口内 VmRSS 峰值 − 就绪后 0.5 秒稳定期中位数（父进程 10 ms 采样，每 stage 独立子进程）。
