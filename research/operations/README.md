# Research operations

One-shot local operations take all evidence as explicit inputs. They do not discover latest files,
read the clock, schedule work, or change lifecycle state. The ADR-0098 resolver (`authority.py`)
reads its authorities only at explicitly pinned identities (a Lifecycle Registry head, a v3 dataset
id + manifest hash) and an explicit evaluation time `as_of` (ADR-0098 修订 2), and runs one window
backtest through the `BacktestProvider` protocol.

| Operation | Purpose | State |
|---|---|---|
| `degradation.py` | Validate explicit ACTIVE-history / PASS baseline / exact frozen Profile / freeze registry / recent metric manifest bindings, then recompute the ADR-0049 degradation check. The caller-supplied lifecycle is not claimed to be latest; observation truth is not independently verified. Report writing with evidence uses schema 1.1.0 through `research.reports.write_degradation_operation`. | `CODE_COMPLETE / DEBUG_PENDING`; no tests or Phase 11 acceptance yet |
| `degradation_cli.py` | One local invocation of the existing degradation operation and append-only report writer. Every artifact, UTC window, freeze registry + external anchor, and reports root is an explicit argument; it does not combine with a research loop. Two mutually exclusive modes (ADR-0098 §4): caller-declared `--lifecycle` + `--recent-manifest` (unchanged; stdout `evidence=caller-declared`) or `--authority-registry --authority-head <hash>\|latest --dataset-id --manifest-hash --authority-as-of <UTC>` (stdout `evidence=authority`; 修订 2: `as_of` not before `--window-end`, the registry is opened with the read-only `LifecycleRegistry.open_snapshot` — no lock, no anchor repair write). The catalog, decision pipeline and backtest provider come from `--authority-environment MODULE:CALLABLE` (ADR-0098 修订 1: trusted deployment factory, resolved like the ADR-0095 worker `--factory`, returning an `AuthorityEnvironment` or a context manager yielding one) or from an embedding caller's `main(..., authority_environment=...)`; without either the mode refuses with `authority_environment_unavailable` after verifying the pinned head. Optional `--authority-anchor <path>` verifies the snapshot against its external anchor (any mismatch is refused as `lifecycle_unavailable`); `evidence.authority.lifecycle.anchor` (and stdout `anchor=`) records `present` / `absent`. | `CODE_COMPLETE / DEBUG_PENDING`; the authority mode is tested (ADR-0105 §7) in `tests/research/operations/test_authority_cli.py` / `test_authority_resolver.py`; no Phase 11 acceptance yet |
| `authority.py` | ADR-0098 resolver: `resolve_degradation_inputs` derives, as of an explicit `as_of` (UTC, `>= window.end`; ADR-0098 修订 2), the lifecycle (read-only Lifecycle Registry snapshot replayed at an explicit head and truncated to `occurred_at <= as_of`; it must end in ACTIVE, entered no later than the window start, with no transition in `(window.start, as_of]`) and the recent metrics (closed `MONITORING_METRICS` registry calling the validation function of each baseline gate, over one window backtest of the pinned v3 manifest's proven bars read with `price_cutoff=as_of`, keeping bars with `interval_end <= window.end` that must tile the window; the declared instruments must equal both manifests' universe members; params compared as canonical JSON) and returns an `AuthorityProvenance` (including `lifecycle.anchor` = `present` / `absent`, the explicit `as_of` and the `BaselineMetricSet` content hash, both re-checked by `run_degradation_check`) that `run_degradation_check(..., authority=...)` writes as `evidence.authority`. Refusal codes include `metric_undefined`, `source_scope_mismatch`, `source_conflict`, `source_incomplete`. The target source's identity also declares its decision grid (step, warm-up) and initial equity, which must equal (canonical JSON) the `execution` block of the baseline run's `hlens.p11.inputs@1.0.0` record (ADR-0100 修订 2: `research.experiments.run_inputs`, written by every new research-loop run into its hashed `repro.params`, so it is bound by the run's `experiment_hash`; no `core/` change; the baseline params compared with the target source's are its strategy params without the record); a baseline run without a valid record — every run from before the amendment, never backfilled or inferred (H3 / H6) — is refused with `execution_unrecorded`. The record is copied into `evidence.authority.execution.baseline_run_inputs` (`hlens.p11.authority-provenance@1.2.0`). ADR-0100 item 3: the closed registry `MONITORING_METRIC_DEFINITIONS` (`hlens.p11.monitoring-metrics@2.0.0`) selects a definition by the metric **and** the gate its baseline cites (id or template with `<i>` / `<seed>`, optional `.instrument.<name>`), and records `definition_id@version`, the concrete gate id, `evidence` and `window_scope` in `evidence.authority.metrics`. `window_returns` (the window backtest): `breakeven_cost_multiple` @ G4.cost_stress.breakeven, `breakeven_cost_multiple_vs_stress` @ G4.cost_stress.<i> (`cost_stress_check`), `positive_window_fraction` / `max_window_pnl_share` (`walk_forward_check`, Profile walk-forward windows). `window_validation` (the baseline `PipelineBacktestValidator` re-run on the window's proven bars with the baseline setup's own inputs — `WindowValidationBinding`, checked against the run and the report's own gates; labels from the run's recorded Outcome definition as evaluation target only): G1 shuffle / shift control p-values (base, per-seed, min over seeds), G2 `effective_independent_trades` / `breakeven_cost_multiple` / `breakeven_cost_multiple_vs_stress` / `percentile_vs_random_entry_null`, G3 `net_mean_hac_p_greater_adjusted`, G4 overfitting (PBO / 1−DSR), parameter neighbourhood, time alignment, delay stress, state share, capacity, cross-asset. Definitions over the Profile's fixed walk-forward folds / windows need the window inside the research window, else `metric_undefined`; every G5 gate and the reported-only G2 items are always `metric_undefined`; a `window_validation` metric without a binding is `metric_inputs_unavailable`; with the record, the binding's `metadata.family_trial_count`, `seed`, `control_seeds`, `robustness.cscv_partitions` / `.impact_coefficient` and — when it gives `state_labels` — its `state_labels_identity` must each equal the recorded value exactly (canonical JSON; else `baseline_binding_mismatch`), and then no dependency is unrecorded; without the record, a definition whose gate depends on a validator input the baseline does not record (`family_trial_count`, the validation seed, a `param:` CSCV partition count / impact coefficient, a state labeller) is `baseline_input_unrecorded` — by default `G3.*`, `G4.overfitting`, `G2.null_model_percentile`, and with single-seed baseline controls also the base G1 controls and every `G2.*` gate; the binding's `declared_instruments` must equal the pipeline's instruments. A failed structural gate of the re-run (G0 binding / execution gates; G1 `outcome_not_input`, `label_blind_sides`, `sealed_oos_excluded`, also per instrument) refuses every metric of that re-run. A function's own insufficient-evidence gate, or a stage the validator did not run, is *missing*. Not imported by the ADR-0074 operator or the API. A `requires_research_window` definition asked for a window outside the Profile's research window stays `metric_undefined` and the message says why and cites ADR-0105 (D-P11-WINDOW: a recent window supports only metrics that do not depend on the research window; such metrics should not be among the Profile's degradation thresholds). | `CODE_COMPLETE`; tests (ADR-0105 §7) in `tests/research/operations/test_authority_{lifecycle,refusals,metrics,execution,resolver}.py` and `test_run_inputs.py` (no Phase 11 acceptance) |
| `authority_environment.py` | ADR-0100 item 4: `default_environment` (use as `--authority-environment research.operations.authority_environment:default_environment`) returns a context manager yielding an `AuthorityEnvironment` and closing the catalog / storage adapters. Data plane from `infrastructure.settings.Settings` (PostgreSQL SQL catalog + warehouse, `LocalFileStorageAdapter`, `DatasetBuilder` → `DatasetCatalog`); the v3 `StreamingEvidenceVerifier` from the explicit, trusted `--authority-evidence-verifier MODULE:CALLABLE` CLI argument (`default_environment(evidence_verifier=...)`, same `load_factory` validation; never from the environment or `.env`; its Dataset rule / run bounds / Quality factory are not settings); baseline run, manifest hash, strategy spec (+ risk policy), cost model, label spec, initial equity and decision grid from `HLENS_AUTHORITY_*`; the backtest provider from the plugin registry by the run's recorded `name@version` (composition-root constructor table, recorded descriptor hash required); the decision pipeline (`StrategyWindowTargetSource`: recorded strategy / risk provider built with exactly the baseline spec, the run's strategy params without its ADR-0100 修订 2 run inputs record, `CandidateTrialRunner`, signals from the window's bars only, instruments = the baseline manifest's universe). Optional validation binding with `HLENS_AUTHORITY_VALIDATION_METADATA` (+ seed, robustness params, control seeds, market benchmark, bar volume). Any missing or invalid setting → `authority_environment_unavailable` naming every missing variable (the CLI prints the names, never values). | `CODE_COMPLETE`; file-level checks tested (ADR-0105 §7) in `tests/research/operations/test_authority_environment.py`; the data plane (PostgreSQL catalog, v3 verifier) is not opened by any test |
| `baseline_export.py` | ADR-0105 §3: `python -m research.operations.baseline_export --report <ValidationReport.json> --run <ExperimentRun.json> --gate metric=gate_id [--gate ...] --output <baseline_set.json>` writes the `BaselineMetricSet` JSON the degradation CLI reads (`--baseline-set`). The mapping is only the explicit `--gate` flags (nothing inferred); the report must be PASS and belong to the run (`run_id`, `experiment_hash`); each pair selects one closed-registry definition and is checked with the resolver's `_check_baseline_gates` (one gate, the definition's exact label, an exact value; `G5.*` and reported-only gates refused). Any missing / mismatching input is refused (exit 1) and the output is created exclusively (never overwritten). | `CODE_COMPLETE`; tests in `tests/research/operations/test_baseline_export.py` |
| `degradation_batch.py` | ADR-0105 §4: `run_batch(manifest, *, reports_root) -> BatchResult` and `python -m research.operations.degradation_batch --manifest <toml> --reports-root <dir>`. The strict TOML manifest (`format = "hlens.p11.degradation-batch@1.0.0"`, one `[[entry]]` per check with every `degradation_cli` argument except `--reports-root`; unknown / missing keys refused before anything runs; relative paths resolve against the manifest directory) is run entry by entry **in-process through `degradation_cli.main`** (no subprocess). No discovery, no "latest", no clock (windows and `authority_as_of` are in the manifest); a failing entry is recorded and the next one runs; exit `0` all ok, `1` any entry failed, `2` manifest refused. A degraded result is a successful entry (evidence only). The external scheduler (ADR-0049) decides when to call it. | `CODE_COMPLETE`; tests in `tests/research/operations/test_degradation_batch.py` |

The operation deliberately refuses to run until the exact Profile has a verified ADR-0062 freeze
record and external anchor. An empty registry or missing observation source is not interpreted as
healthy. The CLI refuses missing registry files before opening the registry; opening an existing
freeze registry takes its exclusive lock and may complete the registry's documented anchor-recovery
step. The Lifecycle Registry is only read, as a lock-free snapshot (ADR-0098 修订 2 §6).
Keep the reports root separate from the freeze-registry root.
Use only one CLI process per reports root at a time: the report writer is append-only and
content-addressed but does not supply a cross-process directory lock.

Run `python -m research.operations.degradation_cli --help` for the required arguments and
`docs/plans/p11-degradation-operator-spec.md` for input JSON shapes and evidence boundaries.

ADR-0067 rule 5 matching (ADR-0098 修订 1 item 4): `compare_gate` records exact-valued gates with a
comparator suffix (`breakeven_cost_multiple[>=]`); the baseline check strips exactly one `[>=]` /
`[<=]` suffix before comparing the gate's metric name with the degradation metric key.

The Lifecycle Registry's only write path is `python -m infrastructure.registry.lifecycle_cli
{append,show-head}` (ADR-0105 §2; not part of this package, never imported by `research/loop/`,
the operator or `apps/`): `append` needs `--transition <json with occurred_at>`, `--expected-head
<record hash>` and exactly one of `--anchor <path>` / `--no-anchor`, and writes nothing without
`--commit`.
