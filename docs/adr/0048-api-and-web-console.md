## 裁决

1. `apps/api`：FastAPI 应用工厂 `create_app`（Provider 注入），只做编排与校验，不含业务规则、不 import `research/`；OpenAPI 导出到
   `apps/api/openapi.json` 并由测试校验为最新。首批只读端点：健康、契约清单、生命周期转移、知识检索。
2. `apps/web`：Vite + React + TypeScript 骨架，只经 OpenAPI 生成的类型访问后端（`npm run gen:api`）；依赖只声明、未安装（项目本地
   安装与构建属调试阶段；不涉及系统软件）。
3. 写操作（实验登记、生命周期推进）等 P7 / P8 / P11 框架后再暴露，并须经授权服务（ADR-0011 的主体与授权约束）。

## Implementation note (console, 2026-09-25)

Builds out the read-only research console on top of the ADR-0048 skeleton, still
FRAMEWORK_IMPLEMENTED / NOT_VALIDATED and still within the original 裁决 above (no new decision;
this only records what was implemented).

**apps/api**

- `apps/api/store.py`: `ReportStore`, a read-only abstraction over JSON artifact files written by
  the research plane at `<reports_root>/<kind>/<id>.json` — `apps/api` still never imports
  `research/` (tested by `tests/test_architecture_boundaries.py`). `ReportKind` covers the four
  kinds the task asked for: `validation_report`, `research_loop_round`, `state_strategy_matrix`,
  `router_paper_run`. Every report is served through one minimal envelope
  (`ReportEnvelope`: `kind`, `id`, `created`, `payload: dict`, `content_hash`), so a new report
  kind is just a new subdirectory — no contract or endpoint change. `content_hash` is the SHA-256
  of the payload's canonical (sorted-key, compact) JSON.
- New endpoints on `create_app` (now takes `reports_root: Path | None = None`, default `None` ->
  every `/reports/*` call returns an empty list / 404, never an error):
  `GET /reports/{kind}` (list) and `GET /reports/{kind}/{id}` (detail). `{kind}` is validated by
  FastAPI's enum path param (unknown kind -> 422); `{id}` is validated against a safe-filename
  pattern and resolved-path containment check before touching the filesystem (path traversal ->
  400; a malformed JSON file is skipped in listings and raises on direct fetch).
- `apps/api/openapi.json` regenerated (`python -m apps.api.openapi`) to include the new routes and
  the `ReportEnvelope` / `ReportKind` schemas; the existing "committed OpenAPI is current" test
  still passes.
- New tests: `tests/apps/test_reports.py` (store unit tests with `tmp_path`, plus the HTTP layer
  via `TestClient`), covering empty-store defaults, per-kind scoping, malformed-file handling and
  path-traversal refusal.

**apps/web**

- Five read-only pages wired to the endpoints above, each carrying a
  "SIMULATED / NOT_VALIDATED" banner and none of them any order / trading UI (H10): Dashboard
  (health + contract count + per-kind report counts), Validation Reports (list + detail with a
  gate-results table), Research Loop (round timeline, an ECharts bar chart of budget used per
  round, failure counts), Lifecycle (the transition table already served by `/lifecycle/transitions`),
  Knowledge Search (unchanged behaviour, moved into its own page).
- `src/api.ts`: a thin fetch client typed off `src/api.d.ts` (generated by
  `npm run gen:api` from the committed `apps/api/openapi.json`, and itself committed).
  `/knowledge/search` is declared `response_model=None` in `apps/api/app.py`, so it has no
  generated response schema; its shape is typed by hand from `core.domain.research.KnowledgeItem`
  with a comment explaining why.
- Dependencies were installed locally (`apps/web/node_modules/`, gitignored — a project-local
  `npm install`, not a system install; `apps/web/package-lock.json` is committed) and both
  `npm run gen:api` and `npm run build` (`tsc --noEmit && vite build`) were run and pass, all
  wrapped in `systemd-run --user --scope --quiet -p MemoryMax=2G -p MemorySwapMax=0`.

**Left open (unchanged from the original 裁决)**: no write endpoints; state-strategy-matrix and
router-paper-run reports are served by the API and counted on the Dashboard but have no dedicated
page yet (not asked for by this task); a real research-plane writer for these report directories
does not exist yet (P6 / P9 / P10 framework land the report shapes this store already reads
generically).
