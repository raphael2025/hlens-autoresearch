# Research operations

One-shot local operations take all evidence as explicit inputs. They do not discover latest files,
read the clock, schedule work, or change lifecycle state. The ADR-0098 resolver (`authority.py`)
reads its authorities only at explicitly pinned identities (a Lifecycle Registry head, a v3 dataset
id + manifest hash) and an explicit evaluation time `as_of` (ADR-0098 修订 2), and runs one window
backtest through the `BacktestProvider` protocol.

| Operation | Purpose | State |
|---|---|---|
| `degradation.py` | Validate explicit ACTIVE-history / PASS baseline / exact frozen Profile / freeze registry / recent metric manifest bindings, then recompute the ADR-0049 degradation check. The caller-supplied lifecycle is not claimed to be latest; observation truth is not independently verified. Report writing with evidence uses schema 1.1.0 through `research.reports.write_degradation_operation`. | `CODE_COMPLETE / DEBUG_PENDING`; no tests or Phase 11 acceptance yet |
| `degradation_cli.py` | One local invocation of the existing degradation operation and append-only report writer. Every artifact, UTC window, freeze registry + external anchor, and reports root is an explicit argument; it does not combine with a research loop. Two mutually exclusive modes (ADR-0098 §4): caller-declared `--lifecycle` + `--recent-manifest` (unchanged; stdout `evidence=caller-declared`) or `--authority-registry --authority-head <hash>\|latest --dataset-id --manifest-hash --authority-as-of <UTC>` (stdout `evidence=authority`; 修订 2: `as_of` not before `--window-end`, the registry is opened with the read-only `LifecycleRegistry.open_snapshot` — no lock, no anchor repair write). The catalog, decision pipeline and backtest provider come from `--authority-environment MODULE:CALLABLE` (ADR-0098 修订 1: trusted deployment factory, resolved like the ADR-0095 worker `--factory`, returning an `AuthorityEnvironment` or a context manager yielding one) or from an embedding caller's `main(..., authority_environment=...)`; without either the mode refuses with `authority_environment_unavailable` after verifying the pinned head. Optional `--authority-anchor <path>` verifies the snapshot against its external anchor (any mismatch is refused as `lifecycle_unavailable`); `evidence.authority.lifecycle.anchor` (and stdout `anchor=`) records `present` / `absent`. | `CODE_COMPLETE / DEBUG_PENDING`; no tests or Phase 11 acceptance yet |
| `authority.py` | ADR-0098 resolver: `resolve_degradation_inputs` derives, as of an explicit `as_of` (UTC, `>= window.end`; ADR-0098 修订 2), the lifecycle (read-only Lifecycle Registry snapshot replayed at an explicit head and truncated to `occurred_at <= as_of`; it must end in ACTIVE, entered no later than the window start, with no transition in `(window.start, as_of]`) and the recent metrics (closed `MONITORING_METRICS` registry calling the validation function of each baseline gate, over one window backtest of the pinned v3 manifest's proven bars read with `price_cutoff=as_of`, keeping bars with `interval_end <= window.end` that must tile the window; the declared instruments must equal both manifests' universe members; params compared as canonical JSON) and returns an `AuthorityProvenance` (including `lifecycle.anchor` = `present` / `absent`, the explicit `as_of` and the `BaselineMetricSet` content hash, both re-checked by `run_degradation_check`) that `run_degradation_check(..., authority=...)` writes as `evidence.authority`. Refusal codes include `metric_undefined`, `source_scope_mismatch`, `source_conflict`, `source_incomplete`. The target source's identity also declares its decision grid (step, warm-up) and initial equity, which must equal the baseline run's recorded values; the reproducibility tuple records none of them, so every resolution is currently refused with `execution_unrecorded` (integrity fixes 2026-09-30; lifting it needs the baseline run to record them — a contract change, ADR). ADR-0100 item 3: the closed registry `MONITORING_METRIC_DEFINITIONS` (`hlens.p11.monitoring-metrics@2.0.0`) selects a definition by the metric **and** the gate its baseline cites (id or template with `<i>` / `<seed>`, optional `.instrument.<name>`), and records `definition_id@version`, the concrete gate id, `evidence` and `window_scope` in `evidence.authority.metrics`. `window_returns` (the window backtest): `breakeven_cost_multiple` @ G4.cost_stress.breakeven, `breakeven_cost_multiple_vs_stress` @ G4.cost_stress.<i> (`cost_stress_check`), `positive_window_fraction` / `max_window_pnl_share` (`walk_forward_check`, Profile walk-forward windows). `window_validation` (the baseline `PipelineBacktestValidator` re-run on the window's proven bars with the baseline setup's own inputs — `WindowValidationBinding`, checked against the run and the report's own gates; labels from the run's recorded Outcome definition as evaluation target only): G1 shuffle / shift control p-values (base, per-seed, min over seeds), G2 `effective_independent_trades` / `breakeven_cost_multiple` / `breakeven_cost_multiple_vs_stress` / `percentile_vs_random_entry_null`, G3 `net_mean_hac_p_greater_adjusted`, G4 overfitting (PBO / 1−DSR), parameter neighbourhood, time alignment, delay stress, state share, capacity, cross-asset. Definitions over the Profile's fixed walk-forward folds / windows need the window inside the research window, else `metric_undefined`; every G5 gate and the reported-only G2 items are always `metric_undefined`; a `window_validation` metric without a binding is `metric_inputs_unavailable`; a definition whose gate depends on a validator input the baseline does not record (`family_trial_count`, the validation seed, a `param:` CSCV partition count / impact coefficient, a state labeller) is `baseline_input_unrecorded` — by default `G3.*`, `G4.overfitting`, `G2.null_model_percentile`, and with single-seed baseline controls also the base G1 controls and every `G2.*` gate; the binding's `declared_instruments` must equal the pipeline's instruments. A failed structural gate of the re-run (G0 binding / execution gates; G1 `outcome_not_input`, `label_blind_sides`, `sealed_oos_excluded`, also per instrument) refuses every metric of that re-run. A function's own insufficient-evidence gate, or a stage the validator did not run, is *missing*. Not imported by the ADR-0074 operator or the API. | `CODE_COMPLETE / DEBUG_PENDING`; not run, no tests |
| `authority_environment.py` | ADR-0100 item 4: `default_environment` (use as `--authority-environment research.operations.authority_environment:default_environment`) returns a context manager yielding an `AuthorityEnvironment` and closing the catalog / storage adapters. Data plane from `infrastructure.settings.Settings` (PostgreSQL SQL catalog + warehouse, `LocalFileStorageAdapter`, `DatasetBuilder` → `DatasetCatalog`); the v3 `StreamingEvidenceVerifier` from the explicit, trusted `--authority-evidence-verifier MODULE:CALLABLE` CLI argument (`default_environment(evidence_verifier=...)`, same `load_factory` validation; never from the environment or `.env`; its Dataset rule / run bounds / Quality factory are not settings); baseline run, manifest hash, strategy spec (+ risk policy), cost model, label spec, initial equity and decision grid from `HLENS_AUTHORITY_*`; the backtest provider from the plugin registry by the run's recorded `name@version` (composition-root constructor table, recorded descriptor hash required); the decision pipeline (`StrategyWindowTargetSource`: recorded strategy / risk provider built with exactly the baseline spec, `CandidateTrialRunner`, signals from the window's bars only, instruments = the baseline manifest's universe). Optional validation binding with `HLENS_AUTHORITY_VALIDATION_METADATA` (+ seed, robustness params, control seeds, market benchmark, bar volume). Any missing or invalid setting → `authority_environment_unavailable` naming every missing variable (the CLI prints the names, never values). | `CODE_COMPLETE / DEBUG_PENDING`; not run, no tests |

The operation deliberately refuses to run until the exact Profile has a verified ADR-0062 freeze
record and external anchor. An empty registry or missing observation source is not interpreted as
healthy. The CLI refuses missing registry files before opening the registry; opening an existing
freeze registry takes its exclusive lock and may complete the registry's documented anchor-recovery
step. The Lifecycle Registry is only read, as a lock-free snapshot (ADR-0098 修订 2 §6).
Keep the reports root separate from the freeze-registry root.
Use only one CLI process per reports root at a time: the report writer is append-only and
content-addressed but does not supply a cross-process directory lock.

Run `python -m research.operations.degradation_cli --help` for the required arguments and
`docs/plans/p11-degradation-operator-spec.md` for input JSON shapes and evidence boundaries.

ADR-0067 rule 5 matching (ADR-0098 修订 1 item 4): `compare_gate` records exact-valued gates with a
comparator suffix (`breakeven_cost_multiple[>=]`); the baseline check strips exactly one `[>=]` /
`[<=]` suffix before comparing the gate's metric name with the degradation metric key.
