# Research & Validation Constitution

| 字段 | 值 |
|---|---|
| 版本 | **1.0.0** |
| 状态 | **Approved**（2026-09-24，[ADR-0020](../adr/0020-approve-research-constitution-v1.md)）— 只前向适用于此后预登记的实验；批准前没有任何实验依据本文件判定，不得追溯重判 |
| 修改规则 | 仅通过 ADR + Raphael 批准；只前向生效 |
| 本文件**不包含**任何数值阈值 | 数值属于版本化的 [Validation Profile](../architecture/07-validation.md)（Step 2，Phase 4 校准后冻结） |

> 本文件是系统的"宪法"，只写**原则**：必须有哪些门槛、如何使用、如何计数、如何裁决。
> **任何人（包括 AI Agent）不得为了让某个实验通过而修改本文件。**

---

## 第一章 基本原则

- **A1 证伪优先**：每个假设在运行前声明预期方向与最小有意义效应量。
- **A2 预登记**：假设、数据切分、指标、成本模型、所用 Profile 版本在运行前登记且不可变。
- **A3 全记录**：每一次尝试都计入 trial count；失败与成功同等保存。
- **A4 裁判确定性**：通过 / 失败由确定性程序判定，不由 LLM 或主观判断决定。
- **A5 规则稳定**：规则修改只前向生效；不得追溯改变已判定对象的结果。
- **A6 成本真实**：所有收益指标必须扣除交易成本、滑点与资金费率。

## 第二章 三层结构（ADR-0007）

| ID | 原则 |
|---|---|
| C-A1 | 验证规则分三层：**Constitution**（不可变原则）、**Validation Profile**（版本化阈值与参数）、**Experiment Metadata**（每个实验实际使用的版本与配置） |
| C-A2 | 原则属于本文件；可校准的阈值属于 Profile；单次实验的设置属于 Experiment Metadata。**本文件不得出现临时性数值阈值** |
| C-A3 | 每个实验在运行前绑定一个 Profile 版本，运行后不可更换 |
| C-A4 | Profile 由**确定性映射规则**选定（标的、周期、预登记的研究类别）；研究者不得自选，不得把实验重新归类到更宽松的 Profile |
| C-A5 | Profile 一经被实验使用即**不可变**；新值 = 新版本，只对之后登记的实验生效 |
| C-A6 | 实验结果**不得**追溯修改该实验所使用的 Profile；不得用新 Profile 重新判定已 REJECTED 的对象 |
| C-A7 | 每个 Profile 必须为五类门槛（样本外、最小有效样本量、基准、参数稳定性、成本压力）都给出判定规则；缺任何一类的 Profile 无效 |
| C-A8 | Profile 参数在冻结前必须完成校准（两步冻结的 Step 2）；校准结果是批准依据 |
| C-A9 | 校准**不是**修改本文件的许可 |

## 第三章 泄漏防护（C-L）

| ID | 原则 |
|---|---|
| C-L1 | Point-in-time：只使用 `available_time ≤ t` 的数据 |
| C-L2 | Outcome 永不作为输入 |
| C-L3 | 标准化 / 分位 / 模型拟合只能用训练窗口内数据 |
| C-L4 | 幸存者偏差：标的池按当时可交易集合构建（含已下架标的） |
| C-L5 | 时间序列交叉验证必须 purging 与 embargo；embargo 不短于最长 Outcome horizon（具体长度由 Profile 定义） |
| C-L6 | 必须有自动泄漏检测：随机打乱标签 / 时间平移后效应必须消失 |

## 第四章 数据切分（C-S）

| ID | 原则 |
|---|---|
| C-S1 | 时间顺序切分：Train → Validation → **Sealed OOS** |
| C-S2 | Sealed OOS 对每个假设族只开封一次；开封事件必须审计记录并计入全局预算 |
| C-S3 | 封存区使用**固定日期边界**，不得随运行时间滚动；边界与长度由 Profile 定义，轮换只能发布新 Profile 版本 |
| C-S4 | 必须进行滚动前推（walk-forward）评估；配置由 Profile 定义 |
| C-S5 | 样本外的作用是检验衰减与一致性；显著性判定来自经多重检验校正的检验（第五章） |

## 第五章 统计显著性（C-T）

| ID | 原则 |
|---|---|
| C-T1 | 必须报告多重检验校正后的显著性；trial count 取假设族累计值（含失败尝试） |
| C-T2 | 必须满足最小**有效独立**样本量；重叠持仓与重叠事件必须折算，不得按 bar 数计算。阈值由 Profile 定义 |
| C-T3 | 置信区间优先于点估计；必须使用考虑自相关的方法 |
| C-T4 | 必须与**空模型**（相同交易次数与持仓分布下的随机进出）比较；市场基准按策略类别适用。具体设定由 Profile 定义 |

## 第六章 稳健性（C-R）

| ID | 原则 |
|---|---|
| C-R1 | 参数稳定性：只在孤立参数点上成立的结果无效；邻域定义与下限由 Profile 定义 |
| C-R2 | 状态分解：不得依赖单一市场状态中的少数事件 |
| C-R3 | 跨标的 / 跨时期：必须在声明的适用范围内检验，并按时期分段报告 |
| C-R4 | 成本压力：必须在加压成本下仍然成立；倍数与判定由 Profile 定义 |
| C-R5 | 必须估计冲击成本与可承载规模（容量） |

## 第七章 复现（C-P）

| ID | 原则 |
|---|---|
| C-P1 | 复现元组完整（`docs/architecture/06-experiment.md` §2），其中必须包含 Constitution 版本与 **Validation Profile 版本** |
| C-P2 | 重跑结果一致（确定性部分按位一致或在声明容差内） |
| C-P3 | 不可复现 = FAILED |
| C-P4 | 任何实验在任何时点都必须能重建"当时适用的验证规则"：Constitution 版本 + Profile 版本 + 两者的不可变定义 |

## 第八章 晋升与退役（C-G）

| ID | 原则 |
|---|---|
| C-G1 | 晋升按 [ADR-0006](../adr/0006-strategy-lifecycle.md) 的状态机执行；PAPER 验收与生产部署审查是两道独立关卡 |
| C-G2 | PRODUCTION_CANDIDATE → ACTIVE 需人工批准 |
| C-G3 | ACTIVE 对象必须定义劣化监控阈值（登记时声明，数值由 Profile 定义） |
| C-G4 | DEGRADED 不得直接恢复 ACTIVE，必须经 REVALIDATION |
| C-G5 | 实盘（`execution_mode = LIVE`）需独立 Risk Gate 与授权记录；Phase 13 之前禁止 |
| C-G6 | REJECTED / FAILED 进入 Failure Registry；RETIRED 进入退役记录。两者不混用 |

## 第九章 修改程序

1. 修改本文件需提交 ADR（Proposed），说明动机——**动机不得是"某个实验因此能通过"**。
2. Raphael 批准后发布新版本号。
3. 新版本只适用于此后登记的实验。
4. Profile 的修改同样遵守此程序，并且只能发布新版本，不得就地修改已被使用的版本。
5. "没有任何策略通过"不是放宽规则的理由，而是需要如实报告的研究结论。
